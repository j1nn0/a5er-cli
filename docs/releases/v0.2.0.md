## Summary

v0.2.0 gives the `a5er` CLI three listing commands — `tables`, `columns` and `relations` — so the
common questions about a diagram no longer require reading a JSON envelope. Each one prints a table
plus notes for a human, and on request emits one JSON envelope of its own shape, so a script reads
the same information without a second code path. `inspect` and `validate` keep their envelopes and
their exit codes, and the JSON contract version stays `0.1.0`.

`a5er` reads A5:SQL Mk-2 ER diagram (`.a5er`) files and reports what they declare. It is read-only:
nothing is written to disk, so output from a confidential diagram cannot end up in a checkout or a
commit.

## New commands

`diagram.a5er` below stands for your own file, as in the README.

```bash
a5er tables diagram.a5er                  # entities and views: one table plus notes
a5er columns diagram.a5er users           # one object's columns, by exact physical name
a5er relations diagram.a5er               # every relation, with its endpoints' resolution
a5er tables --format json diagram.a5er    # the same listing as one JSON envelope
```

**`tables`** lists every entity and view the file declares, one row each, with the section, the line,
the kind and the declared, common and effective column counts. A view does not store its columns, so
its counts read `unknown` rather than `0`. The notes close with the object totals, what was omitted,
the diagnostics and the completeness reconciliation.

**`columns`** lists one entity's columns and takes the object's exact physical name as a second operand.
The name is compared exactly and case-sensitively. A view stores no columns, so selecting one prints
no rows and a note saying why, and still exits `0`. A name that selects no single object — no match,
more than one, or a subtype — writes nothing to `stdout` and exits `4`, so an empty result is never
mistaken for an object with no columns.

**`relations`** lists every relation the file declares, naming each endpoint's declared name and
saying whether it resolved, is dangling, or is ambiguous across several candidates. It takes one file
operand and no object selector, and never exits `4`: a file that declares no relations is a complete
answer, not a failed selection. An unresolved endpoint is a finding, so the exit code stays `0`.

`--format` is per command. `inspect` and `validate` accept only `json`, which is also their default;
`tables`, `columns` and `relations` accept `text` (the default) or `json`. Every envelope carries
`contractVersion`, `tool`, `command`, `status`, `source`, `limits`, `unsupported`, `diagnostics` and
`completeness`, plus one payload key at the seventh position — `schema` for `inspect` and `validate`,
`result` for the three new commands.

Commands the roadmap still holds back — such as `export` — do not exist yet: any other command word
exits `2` with the usage text on `stderr` and nothing on `stdout`.

### Exit codes

| Exit | Meaning                                                                                       |
| ---- | --------------------------------------------------------------------------------------------- |
| `0`  | Envelope written. `inspect`: any read that is not `failed`; `validate`: no `error` diagnostic  |
| `1`  | Any `fatal` diagnostic; the envelope is `failed`                                              |
| `2`  | Incorrect usage; nothing on stdout, usage text on stderr, decided before any input is read    |
| `3`  | `validate` only: an `error`-severity diagnostic; the envelope is `degraded`                   |
| `4`  | `columns` only: the name selected no single entity or view; nothing is written to stdout      |
| `70` | `tables`, `columns` and `relations`: the output could not be generated; discard stdout        |
| `74` | `tables`, `columns` and `relations`: the stdout write failed, or stdout closed before the end |

`inspect` never exits `3`: it reports what the file contains, while `validate` decides whether it is
acceptable. An `error` finding under `inspect` still exits `0` and appears on `stderr`.

## Improvements

**Oversized documents are refused instead of processed without limit.** A read now runs against a
processing budget. A document that would need more work than the budget allows is closed before the
later stages run, and is reported as the fatal diagnostic `E_LIMIT_BUDGET` — exit `1`, a `failed`
envelope, and `schema` and `completeness` set to `null`. The refusal names the reason and never the
document's content, and the budget is a bound on this build's work, not a promise about memory use or
a guarantee that a document under it is cheap.

**The listing commands handle their own output stream.** Writing a long listing into a pipe that
closes early no longer crashes the process: `a5er tables big.a5er | head -n 3` exits `0`, and
discarding the output is the caller's decision, not an error. A genuine output-generation failure
exits `70` and a write failure exits `74`, with `74` outranking `70`, so a broken pipe is never
reported as an internal error. After either code, `stdout` may hold any prefix of the listing or
nothing, so discard it rather than parsing it. Even exit `0` means "written to the stream", not
"delivered to a reader".

**The Agent Skill matches the five commands.** [`skills/a5er-cli/`](https://github.com/j1nn0/a5er-cli/tree/main/skills/a5er-cli)
now covers `tables`, `columns` and `relations` alongside `inspect` and `validate`, and its examples
include a shell-safe way to extract one field from a focused command's output. The skill is installed
separately from the CLI, so install the CLI and keep `a5er` on `PATH`. Because the repository's source
can be ahead of the published package, and the version string does not tell them apart, run
`a5er --help` to see which commands the installed binary actually provides.

## Compatibility and requirements

- **Node.js 24 or later.** `engines` declares `node >=24`.
- **The `inspect` and `validate` envelopes are unchanged.** Same keys in the same order, same status
  values and same exit codes as v0.1.2. The processing budget described under Improvements is the one
  behavioural addition on those two commands, and it only changes the answer for a document large
  enough that this build refuses to process it.
- **`contractVersion` stays `0.1.0`.** It is versioned per command and independently of the package
  version, so a consumer keeps selecting its decoder from `(command, contractVersion)` and sees no
  break from this release.
- **Unknown or unparseable content is still preserved.** Sections, keys and lines that are not
  modelled are counted in `completeness` and reported, never silently dropped.

## Installation

```bash
npm install -g @j1nn0/a5er-cli@0.2.0
```

```bash
mise use -g 'npm:@j1nn0/a5er-cli'
```

To run from a source checkout (pnpm 11.28.12) instead:

```bash
git clone https://github.com/j1nn0/a5er-cli.git
cd a5er-cli
pnpm install --frozen-lockfile
pnpm build
node dist/cli.js --version
```

The installation paths above are the ones the README documents. They were verified for v0.1.0 —
installing from the public npm registry and from a locally built tarball, and installing with mise on
macOS arm64, where only the installation and `a5er --version` were checked. The v0.2.0 package itself
has not been separately installed and verified on each platform, so treat a fresh platform as
unverified, and pin the exact version (`npm:@j1nn0/a5er-cli@0.2.0`) where mise might not yet resolve
this release as the latest.
